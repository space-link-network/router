# Решение проблем

## Не открывается `http://my.space/`

1. Откройте панель по IP — адрес печатается в конце установки (по умолчанию
   `http://192.168.1.2/`). Если по IP открывается, значит не сработал DNS-алиас.
2. Перезапустите dnsmasq на роутере:
   ```sh
   /etc/init.d/dnsmasq restart
   ```
3. На клиенте сбросьте DNS-кеш (macOS: `sudo dscacheutil -flushcache`).

Алиас `my.space` резолвится **только** через DNS роутера. Если на устройстве
жёстко прописан сторонний резолвер или включён DoH/DoT (`1.1.1.1`, `8.8.8.8`,
NextDNS, AdGuard DNS и т.п.), запрос идёт мимо роутера и `my.space` не
открывается. Лечение: использовать роутер как DNS-сервер (выдаётся по DHCP
автоматически), отключить сторонний DoH/DoT на устройстве, либо открывать панель
напрямую по IP.

## Панель открывается, но «токен не задан»

Это нормально, если при установке вы нажали Enter или передали `--skip-token`.
Зайдите в личный кабинет [space-link.app](https://space-link.app/routers),
скопируйте токен и вставьте его на экране подключения (или в разделе
«Настройки» → «Токен подписки»).

## Нет защищённого соединения / сайты не открываются

1. Откройте панель → **Настройки → «Служба соединения»**.
   - Если статус красный — нажмите «Перезапустить».
   - Логи движка соединения:
     ```sh
     logread -e sing-box | tail -50
     ```
2. Проверьте активный сервер в разделе «Серверы» (или включите авто-выбор).
3. Проверьте подписку: если статус «заморожена» или «истекла» — продлите её в
   личном кабинете.

## Не хватает места на роутере

Перед установкой убедитесь, что свободно хотя бы ~30 МБ:

```sh
df -h /
```

Если мало — удалите неиспользуемые пакеты:

```sh
opkg list-installed | sort
opkg remove <пакет>
```

## Установщик ругается на «opkg update failed»

Чаще всего у роутера нет интернета. Проверьте:

```sh
ping -c 3 1.1.1.1
```

Если пинг не идёт — проблема с WAN-настройкой роутера, к Space Link не относится.

## После установки пропал интернет / клиенты получают 169.254.x.x

Установщик делает резервные снапшоты сети в `/etc/space-link/backups/` и при
повторном запуске сам пытается починить конфликты dnsmasq. Первое действие —
**запустите установщик ещё раз**, он восстановит недостающее.

Ручной откат конфига dnsmasq из последнего снапшота:

```sh
uci import dhcp < /etc/space-link/backups/dhcp.latest.uci
uci commit dhcp
/etc/init.d/dnsmasq restart
```

Если LuCI на `http://<IP-роутера>/` перестала открываться (наша панель заняла
:80 на основном IP) — верните uhttpd:

```sh
service uhttpd enable
service uhttpd start
```

## Как полностью удалить

```sh
wget -qO- https://install.space-link.app/uninstall.sh | sh -s -- --purge
```

Флаг `--purge` удалит токен и состояние. Без него токен сохраняется для
переустановки.
